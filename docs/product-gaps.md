# Product gaps

This matrix uses only requirements written in `docs/master-plan.md`, `docs/connectors.md`, `docs/adapters.md`, `docs/topology-diagram.md`, and `docs/checklist.md`. Vendor products were read as benchmarks, not as requirements to copy.

Cisco Catalyst Center Assurance 3.3.1 discovers devices into a site hierarchy before assurance, and inventory counts follow the selected site ([setup](https://www.cisco.com/c/en/us/td/docs/cloud-systems-management/network-automation-and-management/catalyst-center-assurance/3-3-x/cisco-catalyst-assurance-user-guide-3-3-x/b_cisco_dna_assurance_3_2_x_ug_chapter_011.html), [inventory](https://www.cisco.com/c/en/us/td/docs/cloud-systems-management/network-automation-and-management/catalyst-center/3-3-x/user-guide/cisco-catalyst-center-user-guide-3-3-x/b_cisco_catalyst_center_ug_3_1_x_chapter_011.html)). HPE Aruba Central inventories devices and alerts with a site filter ([inventory](https://developer.arubanetworks.com/new-central/reference/getdeviceinventoryv1), [alerts](https://developer.arubanetworks.com/new-central/reference/getalertlistv1)). Juniper Apstra keeps blueprint intent separate from device telemetry and raises anomalies when cabling or interface state does not match that intent ([architecture](https://www.juniper.net/documentation/us/en/software/apstra4.2/apstra-server-and-security-guide/topics/concept/apstra-software-architecture-overview.html), [telemetry](https://www.juniper.net/documentation/us/en/software/apstra6.2/apstra-user-guide/topics/topic-map/device-telemetry.html)). Those ideas match this repository's boundary: the browser talks only to the API, a site connector dials out, and simulator data stays labeled. None of those three products is an adapter here.

Missing reference material: there is no separate product requirements document beyond the files above. The original UTEC drawing is the diagrams.net `mxfile` stored at `apps/web/public/drawio/utec.drawio`, recovered from the PNG text chunk. A raster-only import was not used.
